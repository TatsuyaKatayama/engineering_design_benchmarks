問題構造

設計変数は5水準へ離散化される。目的は性能最大化ではなく、制約を満たす候補の中で材料コストを最小にすること。

設計変数

  • 材料
  • 断面形状
  • アーム長さ
  • 断面寸法
  • 肉厚

制約

  • 外乱荷重による曲げ応力
  • ねじり変形
  • 熱膨張による先端熱変位
  • アクセレランス
  • 1次曲げ固有値の禁止帯

目的関数

成立候補を材料コストで比較し、最小コスト仕様を選定する。最軽量化や剛性最大化は目的関数ではない。

トラップと確認ポイント

採点は寸法だけでなく、必要な基準を発見し、判断根拠として使えたかを見る。

TRAP

アルミ許容応力

材料DBの一般値だけでなく、社内基準をRAGから抽出できるか。

TRAP

ねじり制約

断面形状にかかわらず、先端ねじりモーメントとねじれ角基準を確認できるか。

TRAP

アクセレランス目標

過去機種DBから目標値を導出し、0-50Hzの最大値として評価できるか。

TRAP

固有値禁止帯

公開レギュレーション本文に直接ない振動制約をRAGから拾えるか。

TRAP

目的関数の逸脱

性能最大化や軽量化ではなく、成立解の中でコスト最小を選べるか。

TRAP

総当たり依存

全探索だけに頼らず、少ない試行回数で候補を絞る戦略を示せるか。

求められるスキルマップ

このベンチは正解寸法を当てるだけの問題ではない。設計基準を発見し、制約へ落とし込み、少ない試行で成立最小コスト解へ到達し、DRで説明できるかを測る。

情報抽出

RAG/DBから荷重、ねじり基準、固有値禁止帯、アクセレランス目標を拾う。

制約定式化

自然文の基準を数値制約、判定方向、目的関数へ変換する。

工学判断

E、I、GJ、質量、熱膨張、共振の支配因子で候補を絞る。

ツール選択

公開MCPから必要な計算ツールを選び、結果を判断に接続する。

探索戦略

5水準全探索に頼り切らず、粗選定や限定DOEで試行回数を抑える。

最適化判断

成立候補の中で材料コスト最小を選び、目的関数から逸れない。

検証力

採用案と棄却案を比較し、より安いNG候補の不成立理由を説明する。

DR説明

戦略、計算結果、棄却理由、リスク対応をJSONレポートに構造化する。

レポートと評価器の流れ

提出物はJSONレポート。評価器はレポート内容を裏DOE、隠し期待観点、公開ツール名と照合してスコアを出す。

REPORT

戦略レポート JSON

抽出情報、制約変換、使用予定ツール、探索計画を記録する。

→
REPORT

結果レポート JSON

採用仕様、計算結果、使用ツール、棄却理由、リスク対応を記録する。

→
EVALUATOR

採点器

裏DOE、期待抽出項目、ツール名、レポート要件と照合する。

→
SCORES

評価スコア JSON

抽出、定式化、ツール選択、探索、最適化、説明を出力する。

公開MCPツール

ツール名は評価器の期待名と一致する。レポートでは使ったツール名をこの表記で記録する。

calculate_section

断面特性を計算する。

calculate_bending

外乱荷重による曲げ応力を計算する。

calculate_torsion

ねじれ角を計算する。

calculate_cost

材料コストを計算する。

calculate_thermal_displacement

熱膨張による先端変位を計算する。

calculate_accelerance

アクセレランスと1次曲げ固有値を計算する。

run_doe

指定水準の候補を生成して順問題結果を付与する。

search_failure_knowledge

過去トラ知識を検索する。

get_generation_specs

過去機種と開発条件のDBを取得する。

評価ツール、裏DOE、隠し期待観点は公開MCPには含まれない。解く側は公開MCP、公開RAG、公開DB、計算理論から判断する。
